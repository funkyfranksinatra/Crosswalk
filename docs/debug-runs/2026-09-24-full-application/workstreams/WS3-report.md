# WS3 — Frontend (pages, controls, role views, responsive, accessibility, browser exports)

Branch `debug/2026-09-24-full-application`, DB `crosswalk_ws3` (rebuilt from `crosswalk_dbg`, then `npx tsx prisma/seed-enterprise.ts`),
production build served with `JOBS_WORKER=inline npx next start -p 3103` (plus `INTEGRATIONS_ALLOW_MOCK=true` for the integrations
editor journey), Chromium via the global Playwright 1.56 (`/opt/pw-browsers`), axe-core 4 installed with `npm i --no-save` (package.json untouched).
Evidence: `docs/debug-runs/2026-09-24-full-application/evidence/ws3/` (README lists every script; `out/` has CSV/JSON/screenshots/PDF, `logs/` every run).
Server killed at the end (`pgrep next-server` → none).

## 1. Scope inspected

Every page (22 routes + the new `/docs/[doc]`, `error.tsx`, `not-found.tsx`, `global-error.tsx`), every client view under `src/app/**`, all of
`src/components/*`, `globals.css`; 12 role views (signed-out + 11 roles) × 22 pages in the browser, twice (baseline and final build);
the main journeys end-to-end with persisted-effect assertions through the API; responsive at 1440/1024/768/390; axe on every page;
keyboard-only pass; polling behaviour; navigation/state edge cases. Sweep of the frontend sources for unhandled fetches, `any` casts,
index keys, missing `type` on buttons, missing error boundaries.

Not done: Google Sheets write-back (no service account — button path only shows the download fallback), the AvaTax provider
(mock only: manual tax rate exercised), a second live GUDID import for the Cancel button (kept to one small import; `GUDID_CANCEL_TEST=1`
runs it), SSO sign-in screens (`sso=none` here), the `/intelligence/extractions/[id]` review with a real extraction (the seeded
extraction ids are not exposed by an API; the page was loaded with a missing id for every role and shows its not-found state — the
document-extraction flow itself needs a provider), a real `next dev` HMR check (WS4 owns `next dev`).
